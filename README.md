# HTTP-сервер

Домашняя работа по теме «Сетевое взаимодействие и архитектура web-серверов».
Проект реализует статический HTTP-сервер без сторонних зависимостей.

## Возможности

- методы `GET` и `HEAD`, для остальных методов возвращается `405 Method Not Allowed`;
- раздача файлов из настраиваемого `document_root`;
- `index.html` для URL каталогов;
- percent-encoding и query string в URL;
- MIME-типы для HTML, CSS, JavaScript, JPEG, PNG, GIF и SWF;
- потоковая отправка больших файлов без загрузки целого файла в память;
- защита от выхода за пределы `document_root` через `..` и символические ссылки;
- многопоточная обработка с ограничением числа одновременных обработчиков;
- чтение формата `/etc/httpd.conf`, используемого функциональными тестами задания.

## Запуск

Локально:

```bash
python3 httpd.py \
  --host 127.0.0.1 \
  --port 8080 \
  --document-root ./www
```

Параметры можно задать в конфигурации:

```text
cpu_limit 4
thread_limit 256
document_root /var/www/html
```

```bash
python3 httpd.py --config ./httpd.conf.example --port 8080
```

В Docker:

```bash
make docker-build
make docker-run
```

## Проверки

```bash
make test
```

Функциональные сценарии проверяют `GET`, `HEAD`, коды `403`, `404`, `405`,
обработку каталогов и URL, безопасность, MIME-типы и потоковую выдачу файла.
Дополнительно сервер проверен оригинальным набором
[init/http-test-suite](https://github.com/init/http-test-suite): пройдены все
24 из 24 тестов.

Для нагрузочного теста запустите сервер командой `make run`, а в другом
терминале выполните:

```bash
make benchmark
```

Команда использует ApacheBench: 10 000 запросов, конкурентность 100.

## Результаты нагрузочного теста

Локальный запуск на `127.0.0.1`, статический HTML-файл размером 186 байт:

| Инструмент | Параметры | Результат | Ошибки |
|---|---|---:|---:|
| ApacheBench | `-n 10000 -c 100` | 2480,91 запросов/с | 0 |
| wrk | `-t4 -c100 -d5s` | 2765,38 запросов/с | 0 |

ApacheBench выполнил 10 000 запросов за 4,031 с; среднее время запроса с
учётом конкурентности составило 0,403 мс. В пятисекундном прогоне `wrk`
средняя задержка составила 36,68 мс. Результаты зависят от оборудования и
текущей нагрузки системы.
